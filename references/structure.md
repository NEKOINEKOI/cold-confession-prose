# 起承转合与碎片重组

> 路由：**只要用户给的素材是碎片状的，就先读这个**，再走改写或补写。
> 现实里用户发来的常常不是文章：时间线乱、详略失衡、夹着议论和无关内容、有的地方一句话有的地方一大段。
> **先搭骨架，再换讲法。** 顺序反了，出来的会是一串漂亮的碎片。

---

## 一、起承转合在这套写法里的样子

| 段 | 干什么 | 这套写法里的形态 | 篇幅 |
|---|---|---|---|
| **起** | 抓住人 | 一个反常的画面或数字，**不解释**（"零字节。"） | 极短 |
| **承** | 铺背景 | 事情怎么开始的；回忆插入；现实主体 | 中 |
| **转** | 出事 | 矛盾出现／反转；第三方介入 | 中 → 短 |
| **合** | 落下来 | **极短的高潮 + 很长的余韵**，母题收口 | 高潮最短，余韵最长 |

**这套写法跟普通文章最大的不同在"合"**：高潮只给几段、笔调到最平，然后余韵慢慢铺开、回到母题。不是在高潮炸开就结束。

## 二、碎片重组六步

### 1. 拆件

把素材切成一条条**事实件**——动作、对话、数字、物件、场景各成一条，先不管顺序。

> 素材："昨天晚上我让 AI 整理知识库，几个小时后 3 个库全没了，桌面软件也开始一个个消失，明天要交的源文件也没了。整个过程中它一直在要权限，我看到都是查看读取的权限，根本没有删除权限。"
>
> 拆成：
> - 让 AI 整理 Obsidian 知识库
> - 3 个知识库没了
> - 桌面软件逐个失效
> - 明天的定制源文件没了
> - 全程在要权限，申请的是查看/读取，没有删除

### 2. 去重去杂

合并重复；删掉议论（见 `rewrite-protocol.md` 第 2 步）和跑题的内容。

### 3. 分类

给每个事实件贴上标签：

| 标签 | 说明 |
|---|---|
| **背景** | 事情之前的状态、起因 |
| **事件** | 发生了什么（按严重程度排） |
| **转折** | 局势改变的那个点 |
| **结尾材料** | 能在结尾以"还在／失效／忘了"形态回来的物件 |

### 4. 排序（按起承转合，不按素材给的顺序）

**关键：不要还原素材的时间顺序。** 把最有冲击力的那个画面或数字提到开头当"起"，然后按"认知推进"排列后续。

### 5. 补缺口

排完发现某一段是空的——比如有头无尾（事情没讲完就断了）、或者"转"那一段太薄。这时候：
- 能问就问用户
- 问不到又必须补的，走 `write-protocol.md`，并列入补写清单

### 6. 配母题

选一个能贯穿四段的物件或动作（标准：它本身就是主题的隐喻，且结尾能以"失效／还在／忘了"的形态回来）。详见 `techniques.md` S2。

## 三、层层递进怎么做到

递进 = 每一段都比上一段更进一步，读者不断拿到新东西。**不是并列罗列。**

| 手法 | 说明 | 例 |
|---|---|---|
| **信息递进** | 每段交付一个新事实，不重复已知 | "删了一半" → "另外两个库也没了" → "软件开始失效" |
| **尺度递进** | 影响范围一圈圈扩大 | 知识库 → D 盘 → 桌面软件 |
| **认知递进** | 叙述者的理解在变 | 以为模型不行 → 换模型还是一样 → 意识到"它跑出 Obsidian 了" |
| **笔调反递** | 事情越来越严重，句子越来越短、越来越平 | 最严重的地方只给一句 |

**第四条最关键，也是这套写法特有的**：**事情升级，笔调降级。**

> 例：三个库没了 → 桌面软件逐个失效 → 源文件没了。
> 事情在升级，但写法是"每死一个，多一个白板图标"——不喊疼，只报数。

**反面（没有递进）**：并列罗列——"先是这样，然后那样，再然后那样"。这是流水账，读者感觉不到推进。

**自检**：遮住任意一段，看后面的段落是否还成立。如果打乱顺序读起来没差别，说明是并列，不是递进。

## 四、碎片的四种常见病

| 病 | 症状 | 药方 |
|---|---|---|
| **时间线乱** | 想到哪写到哪，前后跳跃 | 拆件后按事件逻辑重排，不必还原时间顺序 |
| **详略失衡** | 无关细节写一大段，关键转折一句话 | 无关段压到一两句；关键处反过来展开成工序 |
| **有头无尾** | 事情没讲完就断了 | 先问用户结局；实在没有，用母题收口兜底 |
| **重复** | 同一件事说了两三遍 | 合并，保留最有画面感的那一次 |

## 五、重组示意（碎片 → 骨架）

用户发来的（乱序、碎片）：

> 哦对了那个插件是上周装的 · 我一直点允许 · D 盘瘦了 100 多 G · 助手说恢复出来的都损坏了 · 用的是 MiniMax H3 · 后来换成 agnes 还是一样 · 我让 ChatGPT 问了怎么办它说让我关机 · 码表上显示第二天早上还在的是零 · 我当时还以为是模型不行

归类与排序：

| 段 | 选哪些件 | 为什么放这 |
|---|---|---|
| **起** | "第二天早上还在的，是零" | 最有冲击力的画面，且是结局——先抛出来当钩子 |
| **承** | 挂 MiniMax H3 → 点允许 → 以为模型不行 → 换 agnes 还是一样 | 认知递进：从"模型不行"到"不是模型的问题" |
| **转** | D 盘瘦了 100 多 G → 软件逐个失效 → ChatGPT 让我关机 | 尺度递进：知识库 → 磁盘 → 系统 |
| **合** | 恢复工具扫出来全坏了 → 白板图标比软件多 → 那个上周装的插件还在 | 笔调降级 + 母题收口 |

**注意"上周装的插件"这一件**：它在素材最开头、看起来最不起眼，但它是唯一能在结尾以"还在"形态回来的物件——**碎片里最不起眼的那条，常常就是母题**。

## 六、跟其他步骤的先后

```
碎片素材
  ↓
【本文件】拆件 → 去重 → 分类 → 排序（起承转合）→ 配母题
  ↓
素材完整？ ── 是 → rewrite-protocol.md（改写八步：换讲法）
  │
  └─ 否 → write-protocol.md（先补写，再回改写八步）
```

**顺序不能反**：先有骨架，再谈讲法。骨架歪了，句子写得再漂亮也是一堆碎片。
